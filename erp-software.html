5. Notifications

What this means

In-app notifications and browser push are separate. Enabling push preferences does not register the browser; device registration and server configuration are also required.

Notifications are a major new feature in the final version. They alert users about upcoming birthdays, meetings, events, and meetings that still require attendance to be marked.

5.1 Notification Bell

The bell icon is available in the top bar.

It provides:

A count of unread notifications

A dropdown panel with recent notifications

A Mark all read option

A View all & settings link

Using the notification bell

Select the bell icon.

Review the recent notifications.

Select a notification to open its related page.

Select Mark all read to clear the unread count.

Select View all & settings to open the complete Notification Center.

The dropdown normally shows the most recent notifications. Older notifications can be viewed from the Notification Center.

5.2 Notification Center

Opening a notification link does not bypass normal module permissions. If you do not have permission to view the linked employee, meeting, or event, the system may still restrict access.

5.3 Automatic notification triggers

The current version includes four live automatic triggers.

TriggerCategoryWho receives itWhen it is created
Employee birthdayBirthdayAll active usersAn active employee’s birthday is tomorrow
Upcoming meetingMeetingMeeting creator and attendees with linked login accountsA meeting is scheduled for tomorrow
Upcoming eventEventAll active usersAn event is scheduled for tomorrow
Meeting not markedPending MeetingMeeting creatorA past meeting has attendees but no attendance marked

Birthday reminder

If an active employee’s birthday is tomorrow:

The system creates a birthday notification.

The notification normally includes the employee’s name.

Selecting it opens the employee profile.

Meeting reminder

If a meeting is scheduled for tomorrow:

The creator receives a notification.

Attendees receive a notification if their employee record is linked to an application login.

The notification can include the meeting start time.

Selecting it opens the meeting record.

Event reminder

If an event is scheduled for tomorrow:

All active users receive an event notification.

Selecting it opens the event record.

Pending Meeting notification

A Pending Meeting alert is created when:

The meeting date has passed.

The meeting has attendees.

None of the attendees have been marked as attended or not attended.

The meeting has a creator.

This alert reminds the creator to update the meeting attendance.

Marking meeting attendance closes the condition that causes the pending-meeting alert.

5.4 Notification timing

Notification triggers are checked while the application is being used.

The system normally checks for due notifications no more than once every 15 minutes.

A notification may therefore not appear immediately after the employee, meeting, or event is entered.

Refreshing or opening another page later allows the system to check again.

The system also prevents the same source from repeatedly creating the same notification within its duplication-control period. This is especially important for birthdays and annual events.

5.5 Notification Settings

Notification Settings are available from:

Notification Center → Settings

The settings page contains personal notification preferences.

In-App Notifications

In-App Notifications are always enabled.

This provides the notification history and cannot be completely switched off.

Push Notifications

The Push Notifications setting allows notifications to be sent to a registered browser or device.

Important:

Turning on this setting does not register the device automatically.

Use Enable Notifications to register the current browser.

Push delivery requires compatible browser support, user permission, and server configuration.

Notification Sound

When enabled, the system can play a sound when a new notification arrives while the application is open.

Birthday Notifications

Controls birthday alerts.

Meeting Notifications

Controls meeting-related alerts configured through this preference group.

Event Notifications

Controls company-event alerts.

Approval Notifications

This category is available for future approval-related alerts. In this version, no live approval trigger has been connected yet.

Finance Notifications

This category is available for future invoice, due, or finance alerts. In this version, no live finance trigger has been connected yet.

Saving preferences

Turn the required options on or off.

Select Save Settings.

A success message confirms that the preferences were saved.

A user who has never opened Notification Settings normally has the standard categories enabled by default.

5.6 Browser Push Notifications

Push notifications allow supported browsers to display a notification even when the application is not open.

Before enabling push notifications

The following are normally required:

The website must be served over HTTPS or a supported local development address.

The browser must support push notifications.

Browser notification permission must be allowed.

The server must be configured for push delivery.

The application service worker must be publicly accessible.

The administrator must configure the push service and VAPID keys.

If push is not configured on the server, the Notification Settings page displays a message explaining that push sending is not ready. In-app notifications continue to work normally.

Enabling push notifications

Open the Dashboard or Notification Settings.

Select Enable Notifications.

Allow the browser notification request.

Wait for the device to register.

Confirm that the device appears under Registered Devices.

Registered Devices

The Registered Devices section shows each subscribed browser or device.

It may include:

Device label

Date added

Last-used time

Testing a device

If server push is ready:

Open Notification Settings.

Find the device in Registered Devices.

Select Test.

Check the browser or operating-system notification.

A successful test confirms that the device can receive push notifications.

Removing a device

Open Notification Settings.

Find the device.

Select Remove.

Confirm the action if prompted.

Removing a device stops future push notifications to that browser.

16. Troubleshooting

What this means

Check permissions, dates, preferences and device registration before reporting a fault.

16.1 The notification bell does not appear

Confirm that:

You are signed in.

The final-version files were uploaded completely.

JavaScript is enabled in the browser.

The browser is not blocking required scripts.

16.2 A notification did not appear

Check the following:

The birthday, meeting, or event date is correct.

Employee birthdays require an active employee record.

Meeting reminders require the correct meeting date.

Attendees must be linked to login accounts to receive meeting reminders.

Event reminders require the correct event date.

The system checks due notifications periodically and may not generate the alert immediately.

16.3 News & Events does not appear on the Dashboard

The News & Events and Event Calendar sections require permission to view HR employee-related information.

If the section is missing, ask the administrator to review your role permissions.

16.4 A meeting appears in the calendar but no reminder was received

Possible reasons include:

The meeting date is not tomorrow.

The attendee is not linked to a user account.

Meeting notifications are disabled in personal settings.

Push is not enabled or the device is not registered.

The server push service is not configured.

16.5 Push Notifications are not working

Check the following:

The browser supports push notifications.

The website is opened through HTTPS or a supported local address.

Browser notification permission is set to Allow.

Push Notifications is enabled in Notification Settings.

The current device appears under Registered Devices.

The administrator has configured the push service and VAPID keys.

The service worker file is publicly accessible.

Use Test on the device to confirm delivery.

If the settings page says push is not configured on the server, in-app notifications will still work, but browser push cannot be sent yet.

16.6 Notification sound is not playing

Check that:

Notification Sound is enabled.

The browser is not muted.

Operating-system notification sound is enabled.

The browser tab or window is allowed to play sound.

16.7 Approval or Finance notifications are not being generated

Approval and Finance preferences are included for future use. In the current version, no live approval or finance trigger has been connected to those categories.

16.8 The same notification appears again

The system normally prevents repeated notifications for the same source within its duplication-control period. If a notification appears again later, it may be:

A new meeting

A new event

The next annual birthday occurrence

A different underlying record

16.9 A menu or button is missing

A missing menu or button normally means the role does not have the required permission. Contact the system administrator.

16.10 A report shows no records

Check:

Date range

Branch filter

Status filter

Search text

Whether records exist for the selected period

Role permissions

16.11 Push permission was blocked

If the browser notification request was blocked:

Open the browser’s site settings.

Find notification permission for the application address.

Change it from Block to Allow.

Return to Notification Settings.

Select Enable Notifications again.

sw.js

minishlink/web-push

Browser support

Browser permission

Public service worker

Configured VAPID keys

A working push library

17.5 Notification scheduling
